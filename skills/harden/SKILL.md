# Harden — 환경 하드닝 (L1 권한 · L4 백업 · L5 격리)

분류: **[엄격]** — 각 항목은 **증거 칸을 채워야 완료**다.
"설정함"이라는 서술은 완료가 아니다 (헌법 §1 "규율은 산출물로 강제한다").

에이전트 루프에서 파괴 사고를 막는 층은 세 겹이고, 아래로 갈수록 강하다:
1. **지시문** — 헌법 §5 가드레일 (모델이 무시하면 끝)
2. **훅** — `hooks/block-destructive.sh` (문자열 매칭이라 우회 가능)
3. **환경** — 이 스킬 (권한이 없으면 실행 자체가 불가능)

**L1이 최우선이다.** 훅이 뚫려도 권한이 막는 유일한 층이기 때문이다.

## 점검표

| 항목 | 조치 | 증거 |
|---|---|---|
| L1-1 앱 계정 DDL 권한 제거 | `REVOKE CREATE`, 스키마 소유자를 관리 계정으로 | 앱 계정으로 `DROP SCHEMA` 시도 → 거부 출력 |
| L1-2 마이그레이션 계정 분리 | DDL 전용 계정, 앱 접속정보에서 제외 | 계정별 권한 조회 결과 |
| L4-1 백업 스케줄 등록 | cron/systemd timer, 일 1회 + 마이그레이션 전 | 스케줄 목록 출력 |
| L4-2 오프사이트 사본 | 다른 물리 드라이브로 미러 | 대상 경로의 최신 백업 파일 목록 |
| L4-3 복원 훈련 | 스크래치 DB로 실제 복원 1회 | 복원 후 행 수 대조 출력 |
| L4-4 실패 알림 | 백업 실패 시 알림 경로 | 의도적 실패 유발 후 알림 확인 |
| L5-1 dev/prod 이름 분리 | compose 프로젝트명·볼륨명·DB명·포트 전부 다르게 | 양쪽 `docker volume ls` / `ps` 출력 |
| L5-2 복원 스크립트 안전화 | 인자 없이 실행 시 종료, prod는 타이핑 확인 | 인자 없이 실행 → 종료 출력 |

## 규칙

- **증거 없이 "설정함"으로 넘어갈 수 없다.** 증거를 못 만들면 미완료로 보고한다
  (부분 완료도 완료가 아니다 — 어느 항목이 왜 막혔는지 적는다).
- **L1을 먼저 한다.** 다른 항목이 아무리 잘 돼 있어도 앱 계정이 DDL을 쥐고
  있으면 사고는 한 번의 잘못된 마이그레이션으로 난다.
- **프로덕션 대상 변경은 반드시 사용자 확인을 받는다.** 이 스킬은 권한을
  줄이는 작업이라 잘못하면 서비스가 죽는다 — 변경 전 롤백 명령을 먼저 적는다.
- 증거 수집 자체가 파괴적이면(L1-1의 DROP 시도, L4-3의 복원) **스크래치
  리소스에서 한다.** 운영 DB에 시도하지 않는다.

## 산출물 — HARDENING.md

프로젝트 루트에 남기고, 재점검 시 이 파일과 대조한다:

```markdown
# HARDENING — [프로젝트명]
점검: [날짜] · 대상: [dev/prod, DB 종류, 볼륨]

| 항목 | 상태 | 증거 | 비고 |
|---|---|---|---|
| L1-1 | 완료 | `psql -U app -c "DROP SCHEMA public"` → ERROR: must be owner | |
| L1-2 | 미완료 | — | 마이그레이션 계정 생성 대기 (사용자 결정 필요) |
...

## 미완료 항목과 사유
- [항목] — [왜 못 했는가, 무엇이 필요한가]

## 재점검 트리거
- 새 DB/볼륨 도입, 배포 대상 추가, 백업 스크립트 변경
```

## 루프 통합

- **write-plan**: 프로젝트에 DB·볼륨이 있는데 `HARDENING.md`가 없으면
  **Stage 1에 harden 태스크를 넣는다**
  (`role: infra · tier: standard · risk: high · verify: HARDENING.md의 증거 칸 전부 충족`).
  risk: high인 이유는 데이터 변형/삭제 영역이기 때문이다 — 리뷰는 사전 승격된다.
- **자동 라우팅** (헌법 §4): DB·볼륨·배포 등 파괴 위험 환경을 새로 도입하거나
  사용자가 안전 점검을 요청하면 이 스킬을 적용한다.
- **훅과의 관계**: `hooks/block-destructive.sh`는 이 스킬의 대체재가 아니다.
  훅은 문자열 매칭이라 `.sql` 파일 경유·변수 조립으로 우회된다.
  L1 권한이 최종 보증이다.
