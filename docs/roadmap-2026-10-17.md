- **장애**: DESIGN.md `## 에러 처리`를 **실패 예시 표** `| 예시 | 실패 상황 | 기대 동작 |`로 바꾸고 product.md F#의 인수 조건에 실패 행으로 편입(별도 파일 만들지 않음). 외부 의존(API·DB·파일)마다 타임아웃·불가·부분 실패 1개 이상. scale=product면 마지막 stage에 런북 태스크(운영 가이드 "장애 시 확인 순서" 작성 — role: docs).
- **규모·설계**: v1.17 scale:이 담당. 추가로 scale=product면 DESIGN.md에 비기능 요구 표(동시 사용자·응답 시간·데이터량) 1개 — 값은 사용자가 준다, 모델이 채우지 않는다.
- **비용 — 사용자 확정 (검토 기록 §7-9): 둘 다.** 루프 토큰 비용은 v1.19로(측정 장치는 v1.16.1에서 먼저 — 아래 참조). 이 버전은 **제품 운영 비용**만 다룬다.
  - 유료 외부 API·인프라를 쓰는 프로젝트: rules.md 규칙으로 호출 상한·캐시·초과 시 동작(예시 포함). brainstorming 제약 질문에 "유료 호출·유료 인프라가 있는가 → 월 예산 상한" 1문항.
  - **scale=product (판매·과금 제품)**: DESIGN.md 비기능 요구에 **운영 비용 추정 표** — 가정(사용자 수·호출 수·저장량) → 항목별 월 비용(인프라·API·저장) → **사용자당 월 비용**. 이 값이 가격 설계의 근거다. 가정 값은 사용자가 주고 모델이 채우지 않는다. 가정이 바뀌면 표를 갱신하는 docs 태스크 — ADR에 "가격 근거" 출처 칸.
  - scale=product의 정의를 v1.17에서 "외부 사용자·돈·개인정보"로 잡았다면 **"판매·과금되는 제품"**으로 명확히 한다(v1.17 Q-17-4 답에 반영 — v1.17이 먼저 끝났으면 이 버전에서 scale 정의를 고친다).
- Phase 1에서 근거 약하면 보류.
